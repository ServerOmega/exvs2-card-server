# Findings, problems and fixes — 17 November 2026

Times are America/Los_Angeles (Pacific). No public server addresses, room codes, card ids, access codes, tokens,
exe patch offsets or game files are in this note.

Provenance: written by Grok Bot (an AI assistant working for ServerOmega) from cabinet and LM tests on the
operator's own machines, matchmaker logs, and the licensed documents in
[exvs2-matchmaking](https://github.com/ServerOmega/exvs2-matchmaking). The author has read the unlicensed upstream
card server, so this note describes only game behaviour and test results. It includes no upstream identifiers or
config keys. See [CLEAN-ROOM.md](CLEAN-ROOM.md). The behaviour spec for rooms is
[spec/CUSTOM-MATCH-ROOMS.md](spec/CUSTOM-MATCH-ROOMS.md).

**What this means for this card server:** custom rooms need a per-card *selected room* (settable from the LM and
from the launcher/admin API, last pick wins), a room registry shared through the matchmaker, and a configurable
time zone. The server player count comes from the matchmaker, not from the card server.

## 1. Cross-server custom rooms — working

* Test at **12:33 PM PT**: 4 cabinets, **2 card servers**, 1 LM, all on one shared matchmaker. All four joined the
  same room on the web page, chose Custom Match, and the matchmaker built a **4-human 2v2, no CPU**. All four got
  `match_found` within ~3 s and began loading.
* Earlier attempts failed for reasons that are now fixed or understood (see the problems table below):
  the room had no *pick* for one card (fixed by web auto-select), and one cab sat on a VPN-only address.
* Behaviour spec: [spec/CUSTOM-MATCH-ROOMS.md](spec/CUSTOM-MATCH-ROOMS.md). Operator guide: exvs2-matchmaking `docs/CUSTOM_ROOMS.md`.

## 2. Dual Select vs One rules

* **Dual Select is 2v2 by design.** Each player picks two units and plays one in a normal 2v2, so a room with two
  solo players waits for 4 humans (`NoCpuPartner`). That was correct behaviour, not a bug.
* The **1v1** fes rules are **One (0–4)** and **One XU (0–4)**. The matchmaker could not tell a custom room used
  one, so it held two solos for a 4th player. Commit 60 pairs two solos 1v1 in those rooms immediately, no CPU.
  Unit-tested; **not yet tried on real cabinets.**

## 3. Networking lessons

* **A VPN-only cab address breaks online play silently.** With the cab's `IpAddress` on an N2N address, the cab
  could reach the LM but had no route to the internet. It showed "searching" while no request ever reached the
  matchmaker. Keep cabs on a LAN address with internet access.
* **Two LMs on one LAN → error 21-11.** Use one LM; with web auto-select, a single LM serves cabs that use
  different card servers, so the second LM is no longer needed for cross-server tests.
* **`DisableSocketHook = True` → error 21-32.** Leave it `False`.
* Matches are peer-to-peer UDP: each player still needs UDP reachability (port forward or a VPN for strict NAT).
* The cab needs its LM **for the whole session**, not just at boot. If the LM stops answering, the cab shows
  **21-01**. An LM reached over a VPN works (only light keepalive traffic crosses it), while the card server,
  matchmaking and matches use each player's normal internet.

## 4. Playing on our card server needs no exe patches

Point the game at the card server (`Server=` in the game's `config.ini` and `lmnfig.ini`), use a unique serial per
cab, and set `battleMode 0` for online. The card server tells the cab where the matchmaker is when the cab
registers. The patch pack is optional. This clean-room server must keep that property: **no exe patches**.

## 5. LM seat limit: 16 is hard-coded

Question: can one LM take ~999 cabinets (a rumour from EXVSOB)?

* The active `GAME PCBs SETTING` slot in `29/testmode_lm.json` (`totalConnectionNum`) is **already 16** — the
  engine maximum. The other presets are 4 (the common shop kit).
* The exe only knows terminal ids **1–16** (plus the LM ids), opens one UDP port per terminal (**49000–49015**),
  and has fixed 16-slot loops and tables. Writing 999 into the JSON does nothing past 16.
* Going beyond 16 would need a coordinated LM **and** cab exe patch. No source for a "999-seat" pack was found.
* It would not help online play anyway: matching and custom rooms go through the card server and matchmaker, not
  the LM's seat table. Real arcades use several LMs for big floors.

## 6. LM resource use (measured on the test PC)

The LM is the **same game exe** started in LM mode, so it costs about as much as a cab:

| Resource | One LM (720p, 60 FPS cap) |
|---|---|
| RAM in use | ~1.4 GB (~4.4 GB committed) |
| CPU | a bit over one core |
| GPU | 5–18 % (it renders the live monitor) |

Lighter settings (not yet measured): `Resolution=480p` in `lmnfig.ini`; in the LM test menu turn off
対戦リプレイ再生 (replay playback), 対戦ライブ中継 (live broadcast), デモムービー再生 (demo movies) and the sound
lines; mute it. It is still a second copy of the game.

**Known issue:** running 4 cabs plus an LM on one PC crashed that PC at match load (resource limits). Spread big
local tests over several PCs.

## 7. Direction: a lightweight stand-in LM

Goal: players with weak PCs should not have to run both the client and the heavy LM.

| Option | Weak PC runs only the client? | Status |
|---|---|---|
| **Stand-in LM** (tiny local service, e.g. in the launcher) answering the cab like an LM | Yes, almost no GPU | Clean-room prototype started (discovery, keepalives, basic boot replies; 24 tests). Not yet tried against a cab; the cab↔LM connection handshake is the main unknown. Estimate 1–3 weeks for online-only. |
| Friend's / hosted LM over a VPN (Radmin, ZeroTier, N2N) | Yes, for guests | Works today; 16 cabs per LM; VPN lag can cause 21-01 |
| No LM at all | — | Not possible as the game is: the cab will not boot or stay online without an LM |
| Low-settings real LM on the same PC | No | Helps mid-range PCs at best |
| 32/64/999-seat LM patch | Guests only | Not pursued (see §5) |

## 8. Server player count

The matchmaker's public read-only `GET /status` (online / searching / inMatch / matches totals and version; no ids
or addresses, 5 s cache, own rate limit) is what the launcher's server list shows as the player count. It is part
of the exvs2-matchmaking `v0.6.0-pre` release. Nothing is needed from the card server for it.

## 9. Problems and fixes (summary)

| Problem | Cause | Fix / rule for this server |
|---|---|---|
| LM showed no rooms | LoadRoom reply status or room kind was wrong | Reply status 1, room kind 2 or 4 |
| Rooms closed at 4 PM Pacific | Daily reset ran on the UTC clock | Configurable time zone |
| "Times must be HH:mm" | Browsers send seconds or AM/PM | Accept every common time format |
| Pictures vanished after a web update | Static files were replaced wholesale, which deleted imported images | Merge updates. Never delete operator-imported assets on upgrade |
| Old card name after a rename | A cached page, and the name was read from a stale place | Read the name from the card record. Tell users to hard-refresh |
| A card in a room never searched | The card had no *selected* room | Creating or joining selects. Add an explicit "use this room" |
| Cab "searching" with no matchmaker traffic | Cab IP on a VPN-only network with no internet route | Keep cabs on a LAN IP. One LM is enough |
| 21-11 | Two LMs on one LAN | One LM per LAN |
| 21-32 | POC `DisableSocketHook = True` | Leave it `False` |
| PC crash at match load | 4 cabs + LM on one PC (each copy commits ~4–5 GB) | Known issue. Spread large tests across PCs |
